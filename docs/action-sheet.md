# 액션 시트 — 설계 (B안)

- 문서 상태: **보류 (구현했다가 되돌림, 2026-08-17)**
- 범위: 선택지를 고르는 자리를 경고 다이얼로그에서 하단 시트로 분리
- 선행 작업: A안(커스텀 다이얼로그를 네이티브까지 확장) 완료

> **되돌린 이유**: 유일한 적용 지점이던 홈 `+` 메뉴를 다이얼로그로 유지하기로 해서
> `showActionSheet`의 호출처가 0개가 됐다. 쓰는 데 없는 코드를 남기지 않으려고 걷어냈다.
> `+` 메뉴는 지금 제목·본문 없이 항목만 보여주는 다이얼로그다.
> 아래 설계는 그대로 유효하니, [떠든 사람](room-community.md) 게시판의 글 `⋯` 메뉴처럼
> 실제 쓰임이 생기면 이 문서대로 다시 만들면 된다.

---

## 1. 문제

`showDialog`는 지금 **두 가지 다른 일**을 하나의 UI로 처리한다.

| 쓰임 | 예 | 맞는 형태 |
|---|---|---|
| **확인** — 되돌릴 수 없는 동작을 막아 세운다 | "이 지출을 삭제할까요?" | 가운데 다이얼로그 |
| **메뉴** — 여러 갈래 중 하나를 고른다 | `+` → 코드로 참여 / 새 챌린지 만들기 | **하단 시트** |

메뉴를 다이얼로그로 띄우면 두 가지가 어긋난다. 첫째, 제목·본문("방" / "원하는 작업을 선택해 주세요.")이 아무 정보도 주지 않으면서 자리만 차지한다. 둘째, 화면 **상단** 버튼을 눌렀는데 **가운데**에서 무언가 튀어나와 손가락이 화면을 가로질러야 한다.

현재 17개 `showDialog` 호출처 중 메뉴는 소수다. 확인용 다이얼로그는 지금 형태가 맞으므로 **갈아엎지 않고 종류를 하나 더한다.**

---

## 2. 설계 방향

`AppDialogProvider`에 **두 번째 표시 방식**을 더한다. 새 프로바이더를 만들지 않는다 — 화면 위에 한 번에 하나만 떠야 하고, 그 배타성은 한 곳에서 관리하는 게 맞다.

```ts
type AppDialogContextValue = {
  showDialog: (title, message?, actions?) => void;
  /** 선택지를 고르는 메뉴. 하단 시트로 뜬다. */
  showActionSheet: (input: {
    title?: string;
    actions: readonly AppDialogAction[];
  }) => void;
};
```

내부 상태는 하나로 유지하고 종류만 구분한다.

```ts
type AppOverlayRequest =
  | { kind: 'dialog'; title: string; message?: string; actions: readonly AppDialogAction[] }
  | { kind: 'sheet'; title?: string; actions: readonly AppDialogAction[] };
```

`AppDialogAction` 타입(`text` / `style` / `onPress`)은 그대로 재사용한다. 두 방식이 같은 액션 모양을 공유하므로 호출처가 옮겨 다닐 때 인자를 고쳐 쓸 일이 없다.

**취소 액션은 시트에서 자동으로 만든다.** 호출처가 `style: 'cancel'`을 넘기지 않아도 배경 탭·뒤로가기로 닫히고, 목록 아래에 "취소" 항목이 항상 붙는다. 넘긴 게 있으면 그걸 쓴다.

## 3. 시각 설계

`SheetTabBar`가 이미 정한 언어를 그대로 따른다 — 하단 도킹, 상단 모서리만 `radii.xl`, 상단 괘선 `palette.line`, 위로 뜨는 옅은 그림자, 세이프에어리어는 종이로 채움.

```
        ⋯ 화면 (어둡게 덮임) ⋯
┌──────────────────────────────────┐  ← borderTopRadius: radii.xl
│              ────                │     상단 그랩 핸들 (장식)
│  방                               │     title (선택)
│ ┌──────────────────────────────┐ │
│ │ 🔗  코드로 참여               │ │  ← 항목: 아이콘 + 라벨, minHeight 56
│ ├──────────────────────────────┤ │     구분은 얇은 괘선(palette.rule)
│ │ ✚   새 챌린지 만들기          │ │
│ └──────────────────────────────┘ │
│ ┌──────────────────────────────┐ │
│ │            취소               │ │  ← 한 칸 띄운 별도 블록
│ └──────────────────────────────┘ │
│         (safe area)              │
└──────────────────────────────────┘
```

- 항목은 **좌측 정렬**. 다이얼로그의 버튼은 가운데 정렬이지만, 시트는 목록이라 좌측 정렬이 스캔하기 쉽다.
- 배경은 `palette.paper`, 항목 구분은 `palette.rule` 얇은 괘선. 다이얼로그처럼 항목마다 초록 채움 버튼을 쓰지 않는다 — 메뉴에서는 모든 선택지가 동등하다.
- `style: 'destructive'` 항목만 `palette.danger` 글자색. 배경은 채우지 않는다.
- 취소는 한 칸 띄운 별도 블록. iOS 액션 시트 관례이자, 실수로 누르기 어렵게 하는 장치다.
- 아이콘은 선택 항목(`icon?: keyof typeof MaterialCommunityIcons.glyphMap`)으로 `AppDialogAction`에 더한다. 없으면 라벨만.

### 애니메이션

`Modal`의 `animationType="slide"`를 쓴다. `react-native-reanimated`가 들어와 있지만 여기서 쓰지 않는다 — 시트가 아래에서 올라오는 것 하나뿐이라 내장 애니메이션으로 충분하고, 제스처(드래그로 닫기)는 넣지 않는다.

**드래그 닫기를 넣지 않는 이유**: 항목이 2~3개인 짧은 메뉴다. 배경 탭과 취소 버튼으로 닫는 길이 이미 두 개 있고, 팬 제스처를 붙이면 `react-native-gesture-handler` 연동과 스크롤 충돌 처리가 따라온다. 그랩 핸들은 "아래로 닫을 수 있다"는 신호가 아니라 시트임을 알리는 장식으로만 둔다.

### 세이프에어리어

`useSafeAreaInsets().bottom`을 `paddingBottom`에 더한다 (`SheetTabBar`와 동일). 홈 인디케이터 위로 취소 버튼이 겹치면 안 된다.

## 4. 적용 지점

**이번에 옮기는 곳은 하나뿐이다.**

| 호출처 | 현재 | 변경 |
|---|---|---|
| [room-home-header.tsx:57](../src/components/room/room-home-header.tsx:57) `openRoomActions` | `showDialog("방", "원하는 작업을…")` | `showActionSheet({ actions: [코드로 참여, 새 챌린지 만들기] })` |

제목("방")과 본문("원하는 작업을 선택해 주세요.")은 **버린다.** 시트가 떴다는 것 자체가 "고르세요"라는 뜻이라 문장이 필요 없다. 항목에 아이콘(`link-variant`, `plus`)을 붙여 `+` 버튼과 시각적으로 이어준다.

나머지 16곳은 전부 확인·알림용이라 그대로 둔다. 앞으로 판단 기준은 하나다 — **되돌릴 수 없는 동작을 막아 세우면 다이얼로그, 갈래를 고르게 하면 시트.**

향후 [떠든 사람](room-community.md) 게시판의 글 `⋯` 메뉴(수정/삭제)도 시트 쪽이다. 이번 작업으로 그 자리가 미리 준비된다.

## 6. 검증

- 수동: ① `+` 탭 → 하단에서 시트가 올라오는지 ② 배경 탭·안드로이드 뒤로가기·취소 세 경로 모두 닫히는지 ③ 항목 선택 후 시트가 닫히고 라우팅되는지 ④ 홈 인디케이터가 있는 기기에서 취소 버튼이 가리지 않는지 ⑤ 기존 확인 다이얼로그(지출 삭제, 방 나가기)가 그대로인지 ⑥ 웹에서도 동일하게 뜨는지.
- `npm run qa` 통과.

## 7. 결정된 것 / 남은 질문

**결정** — 시트 제목은 `title?` 옵션으로 남기되 `+` 메뉴에서는 **쓰지 않는다.** "방" / "원하는 작업을 선택해 주세요."는 아무 정보도 주지 않으면서 자리만 차지했다. 항목만 보여준다.

**남은 질문** — `+` 메뉴 항목에 **"떠든 사람"을 추가**할지. 게시판이 들어오면 자연스러운 자리인데, 홈 카드로 이미 진입 경로가 생기므로 중복일 수 있다.
